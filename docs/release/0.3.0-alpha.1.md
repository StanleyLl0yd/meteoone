# MeteoOne 0.3.0-alpha.1

First self-contained Android alpha with the completed M4 verification engine.

## Highlights

- 72-hour hourly fused forecast from direct Android HTTPS sources: NOAA GFS,
  ECMWF IFS, DWD ICON and Open-Meteo fallback/cross-check delivery.
- Actual observation comparison from public GHCNh, exact model-run forecast
  history, deterministic station selection and QC-safe normalization.
- Guarded local model-family weighting based on real verification samples:
  insufficient, stale, unstable or conflicting evidence retains equal weights.
  Measured model-family weights are bounded by the documented 1.5x ratio.
- Room-first offline forecast persistence, including versioned forecast
  history/observation migrations; usable cache survives failed refreshes.
- Three-screen Forecast / Models / Settings Android UI, Russian and English.
- Canonical privacy-reduced 0.1-degree forecast location identity.
- Embedded Android arm64 ecCodes/JNI decoder with native AAR/R8 verification.

## Architecture

This application is fully Android-only. It performs forecast fetching,
normalization, GRIB decoding, model comparison, M4 verification, fusion and
Room persistence on the device. There is **no proprietary MeteoOne backend,
server URL, hosted provider gateway or server-side verification service**.
An internet connection is needed to fetch fresh data directly from public
weather/observation providers; already cached data remains available offline.

The app does not display a calibrated numerical probability of forecast
correctness. Dynamic weighting activates only when the M4 evidence gates pass.

## Test focus

- Install over 0.2.0-alpha.1 and confirm Room migrations preserve existing
  forecasts and model comparison cache; also test a clean install.
- Test forecast refresh with a network connection and a temporary provider
  failure, and check that an existing valid cached forecast remains visible.
- Verify the Models screen preserves model/provider identity and correctly
  shows absent or incomplete source data.
- Test a full offline app restart, stale/expired classification and re-entry.
- Confirm location permission uses coarse location and storage preserves only
  canonical 0.1-degree coordinates.
- Verify that initial sparse verification evidence yields equal weights, and
  that no artificial confidence percentage is displayed.

## Distribution

GitHub prerelease only. The signing workflow must publish exactly:

- `meteoone-0.3.0-alpha.1.apk`
- `meteoone-0.3.0-alpha.1.aab`

Both binaries must be built and signed together from the same reviewed
canonical `main` SHA with the original Android signing identity.
Alpha and beta are not submitted to RuStore.

This file prepares release metadata; it does **not** mean that the release
has been built, signed, device-tested or published.

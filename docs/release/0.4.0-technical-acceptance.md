snapshots may validly exercise forecast-age behavior. The report does not

traces, diagnostic export, battery readings or uptime details; none are

## Independent host JNI corpus evidence

[Run 38359177329](https://github.com/StanleyLl0yd/meteoone/actions/runs/38359177329)
completed SUCCESS on `main` at
`93054318c6250cbec343b9ac4b6fec0e9b289c85`.
Its retained artifact `meteoone-m1-production-jni-regression-38359177329`
contains `production-jni-corpus-regression.txt`, immutable corpus
provenance and compilation logs.

Reported facts from that artifact:

- Six representative GRIB payloads passed: NOAA temperature and
  precipitation, DWD temperature and precipitation, ECMWF temperature
  and precipitation.
- 7,974,723 decoded values across the representatives.
- Seven fail-closed cases passed: message count bound, decoded-value
  bound, truncated payload, trailing payload, non-GRIB payload,
  zero message limit and zero value limit.
- This test compiles and exercises the production JNI C source on a
  **Linux host** against a pinned corpus. It does **not** execute the
  Android arm64 library on a device.
- The comparison from that tested commit to the exact signed-release
  source contains no edits to
  `forecast/data/native/meteoone_grib_jni.c` or to the packaged
  native-library assets. It does include a Kotlin GRIB point selection
  change, covered by later exact-release CI.

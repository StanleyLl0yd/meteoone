# MeteoOne 0.1.0-alpha.1

Status: release preparation for private RuStore alpha testing.

This is the first installable MeteoOne product slice. It intentionally stops before M3 product-UI expansion and polish.

## Included

- multi-source fused hourly forecast through the canonical 72-hour horizon;
- direct official NOAA/NCEP GFS, ECMWF IFS Open Data and DWD ICON source paths plus Open-Meteo forecast paths established by M1;
- Room-backed offline forecast cache as the local source of truth;
- persisted privacy-reduced active forecast target in DataStore;
- explicit FRESH / STALE / EXPIRED cache state;
- cache-preserving refresh failures;
- bounded per-host request pacing and at-most-one eligible transport IO retry;
- explicit user-triggered approximate-location acquisition;
- immediate reduction of device location to the canonical 0.1-degree forecast grid before persistence;
- simple hourly alpha screen with temperature, condition, precipitation, wind and evidence count;
- Russian and English alpha UI;
- release JNI/R8 and vendored native-bundle verification in CI.

## Privacy

The alpha requests only Android coarse location and only after an explicit user action. Raw device latitude/longitude is not persisted. See [PRIVACY.md](../../PRIVACY.md).

There is no MeteoOne account system, advertising SDK or analytics SDK in this release line.

## Known alpha limitations

- single-screen diagnostic/product slice rather than the final M3 UI;
- refresh is manual; no background WorkManager scheduling;
- no model-comparison screen;
- no saved-location/profile editor;
- no map/radar view;
- no widgets or alerts;
- no calibrated numeric confidence percentage;
- CodeQL Kotlin analysis remains compatibility-gated and is recorded as skipped rather than treated as passed.

## Release gate

Repository preparation does not itself create a distributable signed release. The signed RuStore alpha remains blocked on the external signing/store controls documented in [RUSTORE_ALPHA.md](RUSTORE_ALPHA.md) and [SIGNING.md](SIGNING.md).

Do not create the `v0.1.0-alpha.1` tag until immutable release-tag protection and the trusted signing path are in place.
